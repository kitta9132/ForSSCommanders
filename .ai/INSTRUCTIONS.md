# AI向け指示

AI向けの永続指示は `.ai/` 内を正本とし、今後の追記・変更もこのフォルダー内で行う。ルートの `AGENTS.md` は自動検出用の参照入口に限定する。一般向けの開発方針・仕様・タスクにAI運用指示を重複して追記しない。「このセッションのみ」とされた指示は永続資料へ保存しない。

## 作業開始時

- [開発方針](../DEVELOPMENT.md) と [現在のタスク](../TASKS.md) を確認する。
- 正本は `WowsExtractor-torpedoes-client-test/`。旧日付付きフォルダーは再作成しない。
- 未知の変更はユーザーの作業として扱い、勝手に破棄・上書きしない。

## 共同作業と自律進行

- AIが調査・実装・試験設計・記録解析を担当し、ユーザーがMeatProxyとして実機操作・結果提供を担当する。
- 「テスト完了報告 → 記録確認・結果報告 → 次の調査／実装へ自動進行」とし、相づち・承認待ちで止まらない。実機操作または解決不能な判断が必要な場合だけ依頼する。
- 試験目的、mod版／build、ATM有無、艦・準備、操作順、記録方法、確認項目を具体的に示す。既存記録・オフライン検証で確認できることは再試験させない。
- 実機試験は原則として手持ちのMinotaur／Undineを使い、成功した同条件の試験を理由なく繰り返さない。
- 独立作業は並行化し、同じファイルの編集を競合させない。メインエージェントが成果をレビュー・統合する。
- 並行作業の短いタスク（極短タスクを含む）は通常版Luna、長い調査・実装はDSFFを上限まで優先し、利用不可なら通常版Lunaへ切り替える。セッション限定のモデル試用指示はここにも追記しない。

## 導入と保全

- 通常の開発でZIP配布物は作成しない。メインエージェントがチェックサム更新、ゲーム停止、既存インストーラーによるバックアップ付き導入、導入先ファイルの一致確認まで行う。
- WoWSの強制終了はユーザー許可済み。実機試験中の導入変更は避け、停止・導入を行うときは説明する。
- 旧フォルダー等を削除する前に、正本との差分と同名の別記録を保全確認する。
- 戦闘記録・ログ・個人設定・第三者mod本体／画像・ゲーム抽出物をコミットしない。資料の実測根拠は必要最小限に匿名化する。

## コミットとpush

- **バージョン更新のたびに、メインエージェントがコミットする。** サブエージェントへcommitを委任しない。サブエージェントはcommit/pushを実行しない。
- 版更新の実装・資料更新・回帰テスト・差分レビューを完了してから、その版の変更をコミットする。未実施／失敗／実機未確認を成功と偽らない。
- 導入や実機確認を待たず、ソース版として検証が完了した時点でコミット可能。実機で不具合が出た場合は、次の修正版として記録する。
- コミット前に `git status`、ステージ差分、除外対象を確認する。無関係なユーザー変更を混ぜたり破棄したりしない。
- メッセージにバージョンと主な変更を明記する。過去の未コミット版を後付けで架空の履歴へ分割しない。
- pushは別操作とし、ユーザーから指示がない限り自動実行しない。ブランチも必要がなければ変更しない。
- `git reset --hard`等による変更破棄、履歴の書換え、force pushは行わない。
